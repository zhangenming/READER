# 2026-08-19

## 关键词指示器：「当前」列改为纯黑（早上随手一改）

用户说屏幕上有两条位置指示器，希望把右边那条（=靠近屏幕右边缘的，也就是
类型='当前'，即 `元素.关键词指示器`，在 `.自定义滚动条` 内部那条）的颜色
改成黑色。

### 改了 3 处（app.js）

1. `创建指示器底图`（约 5662 行）新加一个 `类型` 参数：
   ```js
   底图上下文.fillStyle = 类型 === '当前' ? '#000000' : 获取关键词配色(主关键词).深色;
   ```
   注释说明了：当前列靠位置固定不依赖配色，用黑保持一眼可辨；悬停列仍沿用
   关键词配色，便于和正文高亮保持一致。

2. `绘制单列指示器`（约 5556 行）把 `类型` 透传过去，同时给缓存键加上类型：
   ```js
   const 底图键 = `${关键词.id}|${画布宽}|${类型}`;
   ```
   关键点：原本两个 canvas 共用 `指示器缓存.底图缓存`，只按 `关键词.id|画布宽`
   取值；现在 '当前' 永远画黑、'悬停' 仍用配色，必须分开缓存键，否则会出现
   「当前关键词」和「悬停关键词」刚好是同一个词（虽然代码里已经被判 null 拦掉）
   或者用户切换关键词配色后黑/彩混在一起的诡异情况。

3. `index.html` `?v=20260817-06` → `?v=20260819-02`，硬刷时不用清缓存。

### 副作用与边界

- 段缓存 (`段缓存`，按 `关键词.id`) 没动 — 刻度（哪些像素要画）是版面+命中决定的，
  和颜色无关，共享没问题。
- 「悬停」列行为完全不变，仍然沿用 `获取关键词配色(主关键词).深色`（=用户自定义的
  `关键词颜色`）。
- 「当前」列在浅色主题下黑色实色、黑底白字的高亮对比主题下还是能看清（因为指示器
  的 canvas `globalAlpha = 0.45`，黑+0.45 在 `--背景色` `#e9e7df` 上比 navy 略弱
  一点但仍然可辨）。

### 没做的事

- 没顺手把「悬停」也加上 `类型` 维度的细化（比如把悬停列固定为某个对比色），
  只动了用户点名的那一条。
- 没改 CSS（缓存键里的类型是 JS 维度，CSS 里没有相关规则）。
