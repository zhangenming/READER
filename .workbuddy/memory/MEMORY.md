# 项目记忆（READER 原文阅读器）

## 语音翻页事件桥（解耦约定）
- `语音订阅.js`（语音/识别层）与 `app.js`（阅读器/导航层）通过语义事件解耦：
  - 语音识别到指令 → 派发 `语音翻页`，detail `{指令:'上一页'|'下一页'}`。
  - `app.js` 翻页后回传 `语音翻页完成`，detail `{指令,当前页,总页}`。
- 新增语音指令时**只改两处**：`语音订阅.js` 的识别层 + `app.js` 的 `处理语音翻页` 监听，不要互相直接引用。
- 翻页核心函数：`翻页整屏(向上)`（位于 `绑定事件` 作用域），Space / Shift+Space 与语音共用。

## 自动滚动自适应状态
- 已实现「方案 A 密度自适应」：`计算密度自适应目标速度()`（app.js:2164）在主循环每帧调用（app.js:2217）。预计算「句段负担索引」（`构建句段负担索引` 3365 / `计算句段负担` 3409，含句长惩罚），运行时取前瞻 0.3 视口的窗口，按「实际负担 vs 全文平均负担密度」算出密度因子，返回 `基准速度 × 密度因子^强度`。
- 关键常量：强度 0.7（0=关，1=完全按密度反比）、密度因子下限 0.5 / 上限 2 → 速度实际只在基准的约 0.6×–1.6× 浮动；窗口下移 0.3（前瞻）；句长起点 15 字。
- 用户体感「仍要手动来回拧」的根因候选：① 浮动范围窄且锚定「全文平均密度」而非「用户本人」；② 完全内容驱动、无行为反馈（落后/走神不知）。
- 未做的部分：D 节奏包络（窗口内仍匀速，无段首加速/段尾减速/边界微停顿，是「生硬」主因）、C 个人化（不学用户偏好）、B 眼动、E 朗读联动。

## 运行
- 本地服务：`python3 -m http.server 15921 --bind 127.0.0.1`，浏览器打开 http://127.0.0.1:15921
- 语音转录 WebSocket：`wss://localhost:15941`（声音远程服务器，需先在浏览器信任 https://localhost:15941）；URL 参数 `?ws=` / `?room=` 可覆盖地址与房间。
- 页面通过 `?v=` 查询串控制脚本缓存，改动 JS 后需同步提升版本号并硬刷新。
