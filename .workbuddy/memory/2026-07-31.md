# 2026-07-31

## 实现双击关键词跳转 + 修复误建关键词

在原文阅读器（READER）中完成「双击关键词自动跳转」功能，并修复双击误建关键词的缺陷。

改动文件：`app.js`、`index.html`(缓存版本号 → -3)。

### 根因
双击正文时浏览器生成整词/整字选区，`处理鼠标选择结束` 在 mouseup 的 setTimeout 中调用 `读取选择关键词()`，当选区文本不在关键词列表时便 `添加关键词标记` → 误建「仅含单字」的条目。

### 关键设计
- 新增 `dblclick` 监听 `处理高亮双击`（绑定在 `滚动容器`）。
- `处理正文按下` 用 `事件.detail >= 2` 置 `双击待定` 标志（放在 early-return 之前，覆盖空白双击）。
- `处理鼠标选择结束` 在 `双击待定` 为真时跳过 `读取选择关键词`，只清除选区。
- 单击命中项「前进到下一项」改为延迟 `单击判定延迟=200ms` 执行（`执行单击前进`），双击会取消该计时器 —— 这样双击的第一下单击不会先前进一格，保证「当前是否停在首个」判定精确。修饰键(Ctrl/Cmd/Shift)单击保持即时。
- `处理高亮双击`：当前命中 idx===0 跳到末项，否则跳到第 1 项；单命中或目标即当前则仅重绘。

### 验证
- `node --check app.js` 通过。
- 行为：双击高亮词→首/末切换；双击任意处绝不新增关键词；普通单击延迟 ~200ms 前进；Ctrl/Cmd/Shift+单击即时。

## 修复：单击失效（二次修订）

初版把「单击前进」改为 200ms 延迟执行以区分双击，导致单击不再即时、快速连点被吞成双击 → 用户反馈「单击无效」。

### 修订方案（改用即时单击 + 由 dblclick 承担跳转）
- 撤销 200ms 延迟与 `待定单击计时器/待定单击数据/单击判定延迟`。
- 单击命中项**立即**前进，并在第一次点击(detail=1)记录 `双击前命中 = {关键词id, 当前命中idx}`。
- `处理高亮点击` 对 `事件.detail >= 2` 的第二次点击直接 return（不前进）。
- 双击跳转改在 `处理高亮双击`(dblclick) 中执行 `处理双击跳转`：先用 `双击前命中` 撤销第一次单击的前进，再按「当前==0→末项，否则→首项」跳转。
  - 关键：第二次 click 时浏览器已选中整词，`处理高亮点击` 顶部的「选区未折叠则 return」会拦截，所以跳转必须放在 dblclick 处理器（不受选区守卫影响），不能在 click 里做。
- 新增 `安全获取命中边框` 用 try/catch 包裹 `获取元素命中边框`，点到非当前命中项时不再抛异常中断单击导航。
- 误建关键词的拦截（双击待定 + mouseup 跳过读取 + dblclick 清选区）保持不变。

### 验证
- `node --check app.js` 通过；无 `待定单击/单击判定延迟` 残留引用。
- 行为：普通单击即时前进；双击高亮词→首/末切换且不前进一格；双击任意处绝不新增关键词；Ctrl/Cmd/Shift+单击即时。

## 修复：双击跳转的滚动偏移（先下移再跳）

双击时第一次单击已经把页面滚到「下一项」，第二次点击才撤销并跳首/末，导致「先下移一段再跳」。根因：首击滚动在双击判定（第二次 mousedown，约 500ms 后）之前已执行，无法事前知晓是双击。

### 修复
- 新增 `双击前滚动位置`，在单击命中项前进前记录 `元素.滚动容器.scrollTop`。
- `处理正文按下` 在 `事件.detail >= 2`（双击第二次按下，最早可判定点）立即 `取消滚动动画()` 并 `scrollTop = 双击前滚动位置`（瞬移回原位），随后 `dblclick` 从原位干净跳到首/末项。普通 mousedown(detail=1) 清空 `双击前滚动位置`，避免陈旧值误用。
- `处理双击跳转` 起跳前再兜底重置一次 `双击前滚动位置`（防御 mousedown2 未命中的情况）。
- 单击仍即时、不吞键；仅消除双击首击的滚动偏移残留。

### 验证
- `node --check app.js` 通过。
- 行为：双击高亮词直接从双击前视口位置跳到首/末项，不再先下移；普通单击即时前进不受影响。

## 【已撤回】上面的「滚动偏移」方案被用户否决

用户实测「问题更大了」→ 撤回 `双击前滚动位置` 的四处改动，恢复为「即时单击 + dblclick 跳转」的干净版本。原因：mousedown2 瞬移回原位造成明显闪烁，体验更差。该节方案仅作历史记录，代码已不存在。

## 最终方案：300ms 延迟判定（用户选定「做一个300ms的判断」）

重新引入延迟，但改用「每单击各自排计时器、双击统一清空」的判别模型，从根本上消除首击滚动/前进的副作用，且连点不吞。

### 关键设计
- 删除 `双击前命中` 撤销逻辑（首次单击在 300ms 内不会真正执行，无需撤销）。
- 新增闭包局部 `let 待定单击列表 = []`，每次纯单击（detail=1、无修饰键）push 一个 `{计时器}` 项，`window.setTimeout(执行单击前进, 双击判定延迟=300)` 携带本次 `待定数据{关键词id, 点击命中idx, 原始行位置, 原始边框}`。
- `处理高亮点击`：`事件.detail >= 2` 的第二次点击直接 return（不排计时器）；修饰键分支保持即时、在排计时器之前返回。
- 新增 `清空待定单击()`：遍历 `待定单击列表` clearTimeout 并置空；定时器自身到期时先从列表 filter 掉自身再执行。
- `处理高亮双击`(dblclick)：先 `清空待定单击()` 再 `处理双击跳转`，保证从双击前真实位置干净跳到首/末项，无任何滚动/前进残留、无闪烁。
- `处理双击跳转`：去掉 `双击前命中` 撤销，直接用当前 `当前命中idx`（仍是双击前真实位置）→ `当前命中idx===0 ? 末项 : 首项`。
- 误建关键词拦截（`双击待定` + mouseup 跳过读取 + dblclick 清选区）保持不变。
- 缓存版本号 `index.html` → `app.js?v=20260731-4`。

### 结论
单击延迟 300ms 前进（连点不吞：每次单击独立计时器），双击在延迟窗口内被判定后清空所有挂起项并干净跳首/末；因首击计时器恒早于浏览器双击判定(~500ms)前被清空，彻底消除了「先下移再跳」与「单击失效」两个问题。

## 微调：双击判定延迟 300ms → 180ms

用户实测 300ms 停顿感太强、且双击习惯快速连点。依据：人感知点击停顿临界约 200ms；dblclick 在第二次点击完成瞬间触发，延迟只需大于用户快双击的点击间隔（约 80–150ms）即可挡住「先前进一格再跳」竞态。取 180ms（低于停顿阈值、高于快双点击间隔留 ~80ms 余量）。缓存版本号 `index.html` → `app.js?v=20260731-5`。若仍偶发「前进一格再跳」，可降到 150ms。
