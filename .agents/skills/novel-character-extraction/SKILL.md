# 小说人物完整提取

给定一部书，产出**不遗漏、不虚报**的人物名单。本流程对齐《解放战争》人名清单的成熟口径：提及计数规则、存疑待核附录、合称单列、阅读器导入 txt。

## 四条总原则

1. **召回优先**：宁可先多收、后过滤；每一条被过滤的候选都必须留下理由（进附录，可查可翻案）。
2. **证据为准**：每个收录的人名必须在原文中真实出现；严禁凭书名、题材、常识脑补（"写三国的书肯定有荀彧"——原文没有就不收）。
3. **全程落盘**：所有中间产物写进工作目录，中断可续跑、结论可审计。
4. **双通道**：脚本模式扫描（廉价、高频词兜底防漏）+ 逐块精读（语义、别名、身份）。最终名单 = 两者并集经核验。

## 输入与工作目录

- 输入支持：单个 `.txt`/`.md`；含多个章节文件的目录（按文件名自然排序合并）；`.epub`（自动解包）。编码自动识别（UTF-8/UTF-16/GB18030/Big5）。
- 用户没给路径时：先找（`txt/` 目录、当前目录），找到多个候选书时列出让用户挑；实在没有才询问。
- 工作目录默认 `<书籍所在目录>/人物提取-<书名>/`，可用 `--workdir` 覆盖。结构：

```
人物提取-书名/
├── meta.json  chunks/  candidates.json   # 第1步：脚本
├── per-chunk/chunk-0001.json …           # 第2步：逐块精读
├── merged-draft.json                     # 第3步：全局归并
├── verification.json                     # 第4步：脚本核验
└── 人物名单.md  characters.json  人名导入.txt   # 第5步：交付
```

书超大（>80 万字）时先把规模报给用户（块数、预计批次），然后直接按批继续跑，不要停下来等确认——用户要的就是完整提取。

## 第 1 步：分块与候选扫描（脚本）

```bash
python3 "<本skill目录>/scripts/scan_candidates.py" "<书籍路径>" --workdir "<工作目录>"
```

默认每块 10000 字、相邻块重叠 600 字（防止人名被切块边界切漏）。产出 `meta.json`、`chunks/`、`candidates.json`。

扫完读一下 `candidates.json` 的前 100 条（脚本 stdout 也有 top 40 预览），了解候选全貌和高频名单。

## 第 2 步：逐块精读（防漏主通道）

先读 `references/name-rules.md`——识别规则、别名类型、易漏清单、误报清单全在里面，是本步的裁决依据。

然后逐块处理：Read `chunks/chunk-XXXX.txt` → Write `per-chunk/chunk-XXXX.json`：

```json
{
  "chunk": 3,
  "characters": [
    {"name": "沈青梧", "aliases": ["青梧", "沈姑娘"],
     "identity": "青溪镇沈家镖局少镖头，女主角",
     "nonhuman": false, "mentioned_only": false,
     "evidence": "沈青梧握紧剑柄，回头看了一眼听雨楼。"}
  ]
}
```

要求：

- 收录本块出现的**每一个人名**，包括只出现一次的、只在对话/回忆/旁白/书信署名/章节标题里出现的。不确定是不是人名的，先收进来，第 4 步统一裁决。
- 纯代词（他/她/那人）不收；但"那人+姓名"式的首次亮相要收。
- 有名字的动物、精怪、AI、器灵也收，标 `"nonhuman": true`。
- `aliases` 填本块中出现的其他叫法：名、字、绰号、姓+职衔、亲称。`identity` 一句话；`evidence` 必须抄原文短句，禁止改写。
- `mentioned_only: true` 表示本块中只被他人提及、未直接出场。

批量推进：每批处理 20~30 块，批间更新 `progress.md`（一行：已处理块号区间 / 总块数）。**续跑**：已存在的 per-chunk 文件直接跳过，从 `meta.json` 对账缺哪块补哪块，绝不重扫。

## 第 3 步：全局归并

把所有 per-chunk JSON 分批合并成 `merged-draft.json`（书大时增量合并：读入已有草稿 → 并入一批 → 写回，不要把几百个文件一次读进上下文）：

```json
{
  "book": "书名",
  "characters": [
    {"canonical": "沈青梧", "aliases": ["青梧", "沈姑娘"],
     "importance": "主角", "identity": "……", "nonhuman": false,
     "first_seen_pct": 0.03}
  ],
  "collectives": [
    {"name": "青风双侠", "refers_to": ["沈青梧", "顾长风"], "count": 2}
  ],
  "filtered": [
    {"candidate": "听雨楼", "count": 4, "reason": "门派/楼名，非人名"}
  ]
}
```

归并规则（细则见 name-rules.md §别名归并）：

- 同一人的多种叫法并为一条；`canonical` 取全书最常用、最正式的称呼。
- **合称单列**：指代多人的固定搭配（"刘邓""林罗"、并称、并号）进 `collectives`，不并进任何个人。
- 重要性分级：`主角 / 重要配角 / 次要人物 / 仅提及`（口径见 name-rules.md §分级）。史书/纪实类分级失真时，改按阵营/势力分组，分级列保留。
- `first_seen_pct` 用该名字首次出现的 chunk 的 `meta.json → chunks[].pct`。
- **扫描候选兜底**：把 candidates.json 中 count≥2、且没被任何精读结果覆盖的候选逐个过一遍——收录，或 `filtered` + 理由。一条都不能静默丢弃。

## 第 4 步：脚本核验与召回审计（防虚报 + 防漏）

```bash
python3 "<本skill目录>/scripts/verify_names.py" --text "<书籍路径>" \
  --names "<工作目录>/merged-draft.json" --workdir "<工作目录>"
```

脚本做两件事，产出 `verification.json`：

1. **核验（防虚报）**：每个 canonical 和别名放回原文精确计数（子串重叠自动扣除）。处理所有 issues：
   - `canonical 0 次` → 幻觉或写法不符：改正写法或删除，改完重跑；
   - `别名 0 次` → 查上下文改写或移除；
   - `子串警告` → 确认两条是不是同一人、别名归属是否正确。
2. **审计（防遗漏）**：列出名单覆盖不到的高频候选（count≥`--min-count`）。**逐条裁决**：收录进名单，或写进 `filtered` 并给出理由。全部裁决完才能进第 5 步。

## 第 5 步：交付

把核验后的计数并回名单，写三份产物：

**1. `人物名单.md`** —— 报告骨架（按此结构，篇幅随人数伸缩）：

```markdown
# 《书名》人名全清单

数据源：`<路径>` —— 全书约 N 万字 / 分块 M 块 / 编码 xx。

## 一眼看全
| 收录人物 | 提及总数 | ≥100次 | ≥10次 | 仅1—2次 | 合称 |
|---|---|---|---|---|---|

## 提及最多的 30 人
毛泽东(3476)、蒋介石(2238)、…（括号内为提及次数）

## 主角（或：第一阵营）
| 姓名 | 提及 | 别名 | 身份 | 首见(约) |
|---|---|---|---|---|
| **沈青梧** | 13 | 青梧、沈姑娘 | 沈家镖局少镖头 | 全书 3% 处 |

## 重要配角 / 次要人物 / 仅提及（同上表结构）

## 合称（指代多人，不并入个人）
| 合称 | 指代 | 次数 |

## 附录：过滤记录（存疑待核）
| 候选 | 次数 | 过滤理由 |

## 统计口径
- 提及＝该叫法作为完整字符串在全书出现的次数；别名各算各的，不并入 canonical
  （"毛主席"不计入"毛泽东"）；别名与全名的重叠部分已由脚本扣除，不重复计数。
- 身份＝原书上下文的一句概括，只反映本书写法。
- 首见＝名字首次出现的大致位置（百分比），由分块索引推算。
- 过滤≠删除：存疑候选全部保留在附录，可翻案。
```

**2. `characters.json`** —— 结构化全量：`merged-draft.json` 的每个 character 加上 `"occurrences": {"canonical": N, "aliases": {…}, "total": N}`（来自 verification）。

**3. `人名导入.txt`** —— 每行一个 canonical，按提及次数降序（阅读器关键词导入直接可用）。

## 快速模式（仅当用户明确要快）

跳过第 2 步逐块精读：以候选扫描为主体，用上下文抽查裁决，直接产出名单。报告标题和"一眼看全"必须标注**快速模式，可能有遗漏**。默认（用户没说要快）永远走完整流程。

## 红线

- 不许跳过第 4 步直接交付——没有核验的名单一定混着幻觉和漏网候选。
- 不许静默丢弃任何候选：收录或过滤+理由，二选一。
- 不许把"提及次数"算成别名计入 canonical 的混合数——口径混了，报告就不可信了。
