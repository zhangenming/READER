## 三个视图各自回答什么

| 视图 | 问题 | 关键结论 |
| --- | --- | --- |
| SystemContext | 边界在哪，碰了哪些外部系统 | **两个**外部依赖：① 同域静态文件服务（`fetch ./txt/` 目录列表 + `.txt` 正文，`js/内容选择弹窗.js:136`、`app.js:295`），无 API、无 manifest、无鉴权；② **声音远程服务器 `wss://localhost:15941`**（自签名证书，`语音订阅.js:20,160`），可用 URL 参数 `?ws=` / `?room=` 覆盖。仍无后端、无第三方 SaaS。 |
| Containers | 有几个可独立部署单元 | **1 个浏览器文档 + 1 个 localStorage**。`package.json` 无 dependencies、无构建步骤，`txt/` 下 13 个 `.txt` 是唯一的"数据"。 |
| Components | 一个容器内部职责怎么切 | 29 个 `js/` 模块归入 **8 组**，其中 4 处断环回调和 1 个共享可变单例是结构关键。 |

## 三种集成机制，而不是一种

模型里的边按 tag 分成三类，它们是**结构上互不等价**的通信方式——这一点比"有几个模块"更能说明架构：

| tag | 机制 | 证据 | 失效表现 |
| --- | --- | --- | --- |
| `Import` | 编译期 `import` | 144 条，0 环 | 启动即报错，门禁 `verify-模块图.mjs` 能拦 |
| `EventBus` | `window` CustomEvent | `语音订阅.js:121-122` 派发 → `app.js:753,763` 监听，双方**无 import**，只共享 `常量.js:92` 的 `语音事件` | 事件名不匹配则静默无声 |
| `HiddenDataFlow` | `状态.js` 共享可变单例读写 | 实测 90 条向上耦合 | 读到 `undefined`，运行期才暴露 |

`EventBus` 是这条链路上唯一的"真异步"：语音服务器 → WebSocket 收流式转写 → 识别指令 → `dispatchEvent` → `app.js` 的 `处理语音自动滚动`（`app.js:755-763`）→ `执行自动滚动翻页()`（`js/自动滚动.js:378`）。断线重连策略在 `js/常量.js:113-114`：间隔 5000ms、最多重试 2 次后放弃。


## 为什么组件层只画 8 组而不是 31 个模块

C4 的 component 视图要求每个组件有明确的父容器——这里父容器唯一（同一个 document），条件满足。但 144 条 import 边里 **108 条（75%）跨越 1 层以上**，画进单一 C4 视图会得到一张不可读的毛线球，违背「一图一问题」。

因此分工是：C4 负责**边界与职责**（8 组），`dependency-impact-analyzer` 的 Graphviz 负责**连接细节**（31 节点全量）。8 组每个组件的 `description` 里都写明了成员模块清单，可回溯。

## 这个模型最重要的一处表达

组件视图里有**两类语义不同的边**，我用 tag 区分：

- **实线 `Import`**：编译期 `import` 语句，共 19 条聚合边（代表 144 条真实模块边）。这部分构成 **0 环的 DAG**。
- **红粗 `HiddenDataFlow`**：运行期通过 `状态.js` 单例的**跨层反向读写**。这类边在 import 图里**完全不可见**——低层模块结构上不可能 import 高层模块，但它读的是高层写入的值。实测 **90 条**，涉及 19 个读方模块、34 个共享字段；写方分布 L12 `app.js` 60 条、L8（字体设置/自动滚动/查找弹窗）24 条、L11 正文交互 5 条、L7 跳转动画 1 条。DSL 中只画了层级跨度最大的 4 条代表边。

> **注意**：Structurizr 允许同一对元素间存在多条关系，因此 `装配根→排版渲染`、`滚动跳转→排版渲染`、`交互外壳→滚动跳转` 三对上同时挂着一条 Import 和一条 HiddenDataFlow，预览时可能重叠成一条线。以 DSL 文本为准。
> 另外虚线我刻意用标准 `->` + `relationship "HiddenDataFlow" { style dashed }` 表达，而没有用 `..>`——插件自带示例只出现过 `->`，`..>` 未经该预览器验证。若预览器不支持标签样式，退化为不显示虚线而非解析失败。

**读这张图的正确方式**：不要被"0 环"安慰。编译期无环恰恰是靠把跨层通信改走 `状态` 单例和回调注入这两条旁路换来的。

## 假设与不确定项

| 项 | 状态 |
| --- | --- |
| `browserDoc` 与 `store` 划为同一 softwareSystem 下的两个 container | **建模判断**。localStorage 严格说是浏览器宿主的一部分，此处按 C4 惯例把数据存储单列，置信度 medium。 |
| `本地静态文件服务` 具体是哪个服务器 | **unknown**。仓库无启动脚本外的部署配置；`fetch ./txt/` 依赖目录 HTML listing，换服务器可能失效。 |
| 8 组分名的边界 | 前 7 组按职责聚合，置信度 medium；每组成员清单是我依据分层与 import 关系人工归类的结果，**项目源码中不存在这套分组**。 |
| HiddenDataFlow 的 90 条是否真在运行时触发 | 静态读/写点比对得出，**未插桩验证**。 |
| `语音订阅.js` 归为独立 Entry 组件 | 高置信：它只 import `常量.js`，爆炸半径 0，与主链路完全隔离。 |
