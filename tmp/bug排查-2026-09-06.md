## P0 · 阅读统计功能的致命缺陷（未提交改动引入）

以下 5 条全部来自当前工作区未提交的「统计」按钮 + 阅读统计弹窗功能。

### 1. 「内容」按钮被「统计」按钮完全遮挡，点击无效
- 证据：index.html:91-98 新按钮复用了 `class="内容选择按钮"`；styles.css:524 该类声明
  `grid-area: 内容`。`.右下按钮组` 的 `grid-template-areas` 只有 `'滚动 关键词' / '内容 内容'`
  一个「内容」单元格。两个按钮显式置于同一 grid area → 按 CSS Grid 规范彼此重叠，
  DOM 顺序靠后者（统计按钮）绘制在上层，「内容」按钮被完全遮住，无法点击。
- 影响：切换书籍的入口直接不可用。
- 修法：给统计按钮独立的 grid-area（需同步扩 areas 网格），或改用别的 class 不带
  `grid-area: 内容`。

### 2. 弹窗样式全部失效：三个 CSS 变量在整份样式表中未定义
- 证据：styles.css:309-345 使用 `var(--边框色)`、`var(--纸面色)`、`var(--文字色)`；
  `grep` 全表仅有 `--纸张色` / `--边线色` / `--墨色`（styles.css:59-64），三个引用的
  变量均无任何定义 → 边框/底色/文字色全部回落到初始值（黑底黑字级别不可读），
  表格 `border-bottom` 也不渲染。
- 修法：改用既有变量（`--纸张色`/`--墨色`/`--边线色`），或补定义。注意 `dialog` 选择器
  在 styles.css:1573 已钉死弹窗黑白主题变量，本弹窗应与之统一而不是自造变量。

### 3. 键盘守卫「有弹窗打开」漏掉了阅读统计弹窗
- 证据：js/面板.js:10-18 `有弹窗打开()` 只查查找/上下文/词频/内容选择/字体五个弹窗，
  不含 `元素.阅读统计弹窗`。该函数被 键盘控制.js 5 处引用（Z/X 按键滚动、方向键/Space
  翻页、Ctrl 导航、Backspace 回跳全部用它做弹窗内禁用判定）。
- 影响：统计弹窗打开时，Space/Enter/方向键/Z/X/Backspace 全部穿透弹窗作用于正文
  （背景翻页、改变阅读位置）；dialog.showModal() 自动聚焦弹窗，极易在查看统计时误翻页。
- 修法：`有弹窗打开()` 增加 `元素.阅读统计弹窗.open`（元素引用已在 状态.js:208 缓存）。

### 4. innerHTML 拼接未转义的文件名（存储型 XSS 面）
- 证据：app.js:709-716 把 `txt/` 目录 listing 解析出的文件名（内容选择弹窗同源，
  fetch 目录页 `a[href]` 解码而来）直接插值进 `innerHTML` 模板。文件名只经过
  `是有效文本文件名`（查 `.txt` 后缀 + 无路径分隔符）校验，**不阻止 `< > " ' onerror` 等
  HTML 字符**。macOS 文件名合法包含这些字符。验证：文件名
  `x<img src=x onerror=alert(1)>.txt` 会原样注入表格。
- 影响：本地单机应用风险低，但任何往 txt/ 放文件的人（或恶意解压包）都能在统计弹窗
  执行任意 JS。与项目其他弹窗（全部 textContent / createElement 构造 DOM）的安全基线不符。
- 修法：改用 createElement + textContent 构造表格（参照 js/面板.js 的做法）。

### 5. 「本书进度」在列表里显示错书的进度
- 证据：app.js:709-714 行循环里 `名 === 状态.文件名 ? \`${进度.toFixed(1)}%\` : '—'`
  只给当前书填进度。但 `进度` 在 app.js:695-708 由 `获取静止滚动位置()` 计算——当滚动动画
  进行中取的是动画终点，静止时取 scrollTop；而 `总时长`/`今日` 用的是内存统计。
  真正的问题：`当前 = 数据.文本状态?.[状态.文件名]`（app.js:694）取了持久化旧值却从未
  使用（死变量），且当前书行显示的时长是**上次落盘值**而非内存 `统计.书籍滚动毫秒`
  实时值——正在自动滚动时打开统计，当前书时长不含本次会话已累计时长（最长滞后 30s，
  `自动滚动统计保存间隔`），与摘要区的「今日阅读」（含未入账）口径不一致。
- 修法：当前书行改用 `统计.书籍滚动毫秒.get(状态.文件名) + 统计.未入账滚动毫秒`
  （与 js/统计展示.js:30 今日本书滚动后缀 同口径）；删除死变量 `当前`。

另：`打开阅读统计()` 未像其他弹窗一样 `停止自动滚动`（对比 js/内容选择弹窗.js:33），
打开弹窗后自动滚动仍在背景跑、统计数字实时变化且 modal 顶层焦点冲突，属交互缺陷。

## P1 · 存量代码确认的问题

### 6. 自动滚动中，字号控件滚轮被全局 wheel 捕获劫持
- 证据：js/自动滚动.js:352-386 `处理自动滚动滚轮` 绑定在 `window` 且
  `{capture: true, passive: false}`（app.js:328），内部只对 `元素.行距控制` 放行
  （js/自动滚动.js:354），`字号控制` 没有同等豁免；事件命中后 `preventDefault() +
  stopPropagation()`。
- 影响：自动滚动进行中，在「字号」控件上滚轮调不了字号，反而被劫持去改自动滚动速度。
  与 `行距控制` 的既有豁免明显不对称（同为 字体设置 弹窗内的滚轮控件）。
- 修法：js/自动滚动.js:354 的判定改为同时豁免 `元素.字号控制`（或用
  `元素.字体弹窗.contains(事件.target)` 一并豁免）。

### 7. 查找弹窗的 `!` 排除前缀与搭配分析互斥
- 证据：js/查找弹窗.js:312-313 `处理词组分析` 取 `元素.查找输入框.value.trim()` 作为
  `前缀` 原始输入（含 `!`），随后 `查找关键词命中(前缀)` 全文扫描 `!阁老` 这样的字符串
  ——文本中不可能存在，永远返回 0 命中 → 显示「未找到该关键词」并清空分析面板。
- 影响：`!` 前缀（排除某字开头变体）是查找功能已支持的语法（js/查找弹窗.js:188-203
  `解析查找查询`），但一旦使用，搭配分析必坏。验证：文本含「阁老」时
  `includes('!阁老') === false`。
- 修法：`处理词组分析` 改用 `解析查找查询(...)` 的 `查询.目标`，与 `执行实时查找`
  同源；或至少把 `!前缀` 剥掉再扫描。

### 8. 字号增大触发行高联动时，阅读位置向上漂移
- 证据链：js/字体设置.js:675-697 `调整字号` 当 `状态.行高 < 新值` 时同步改
  `状态.行高` 和 CSS `--行高`，但**不做** `调整行高`（js/字体设置.js:741-761）里那句
  `scrollTop *= 新值/旧行高` 的比例缩放；随后 `新排版.键 !== 状态.排版键` →
  `重建并刷新` → js/排版引擎.js:71
  `顶部行idx = Math.floor(获取静止滚动位置() / 状态.行高)` 用新行高换算旧尺度 scrollTop。
- 量化：字号 30→50（行高联动 30→50）、scrollTop=9000px 时，语义上应停在第 300 行，
  实际恢复到第 180 行，向上漂 120 行 ≈ 3600px 内容。
- 影响：小字号+紧行距的配置下调大字号时，阅读位置明显跳退；且
  `恢复阅读设置` 之后的同场景（js/字体设置.js:961 行高=max(行高,字号)）同样受累。
- 修法：`调整字号` 的联动分支补 `元素.滚动容器.scrollTop *= 新值/旧行高`（与
  `调整行高` 同法），或在 `重建行索引` 提交前回调里做缩放。

### 9. Shift 双击阈值内三击误判（轻微）
- 证据：js/键盘控制.js:397-414 双击判定成功后 `shift最后松开时间 = 0` 复位，避免三连击
  误判为新的双击 —— 这点处理了。但**阈值外**首次松开记录时间戳后，若第二次松开恰好
  超过 `shift双击中阈值`（350ms），时间戳被更新为第二次 —— 这是设计内。
  真正的边角：`处理键盘松开` 对 Shift 的判定要求 `!事件.altKey`（js/键盘控制.js:397），
  Alt+Shift 组合松开 Shift 时不复位 `shift按住中`，需等 Alt 松开才由
  `尝试执行待导航` 兜住 —— 状态不残留（下次 Shift keydown 会重置），无实害。
- 结论：复核后无实际 bug，仅记录边角行为。

### 10. 恢复阅读设置期间的全局后写污染（上轮已知，仍成立）
- js/字体设置.js:863-926 `恢复阅读设置` 先整体重置为默认、再按持久化值覆盖，全程
  同步改 CSS 变量与 body 内联。`应用文本`（app.js:859-1019）里 `恢复阅读设置` 之后才
  `提交行索引`；行索引构建是分片 `await` 的，期间用户交互（如调整字号）触发的
  `安排保存持久化状态` 会把**新书的设置快照**写进**旧书的持久化记录**（保存时
  `状态.文件名` 已指向新书，而 `读取阅读位置` 用的是旧索引）。上轮评审已记录
  （commit d0a7873），本报告确认在当前 HEAD 仍成立，修法见该 commit 信息。

## P2 · 复核确认无 bug / 降级的疑点（防重复排查）

  前置/后置片段各自独立、无跨行残留 —— 无 bug。

  统计弹窗摘要区同口径（问题只在第 5 条的表格行用了持久化旧值）。
- **持久化回退/损坏备份状态机**：18 项门禁测试全过（verify-persistence-migration），
  空字符串按损坏处理、SecurityError 不覆盖原值 —— 实现与测试一致。
- **双 rAF 循环互斥**（commit be0c239）：`开始自动滚动` ↔ `开始按键滚动` 互抢 +
  `处理滚动` 的 `滚动动画目标||滚动帧` 双重短路 —— 复核无竞态。
