二、现存问题（按严重度分级）

P1 启动异常路径：第二次读取持久化数据无保护，损坏数据 → 整个应用白屏

启动() 里第 175 行对 读取持久化数据() 做了 try-catch，但 读取初始文件名()（第 233 行）内再次裸调同一函数，无任何保护。读取持久化数据() 在 JSON 损坏时抛 SyntaxError、结构校验失败时抛 TypeError——只要 localStorage 里的数据坏了，异常会从模块顶层逃逸，整个 app.js 模块执行中断，页面完全不可用，且用户看不到任何错误提示（只在控制台）。第一次 try-catch 因此形同虚设。

读取初始文件名() 套同款 try-catch；或读取持久化数据() 失败时清除坏键并返回默认值。约 5 行改动，风险极低。

P2 绑定事件() 仍是 1622 行巨石

实测 绑定事件() 占 app.js 剩余代码约 65%，内部还嵌着词组分析等业务处理函数。这是重构「下半场」未完成的部分：事件绑定天然属于组合根，但 1622 行单函数的可读性代价已经超过「集中绑定」的收益。

不急于继续拆。下次要动 app.js 时按交互域（键盘/指针/弹窗/语音）分批搬移，沿用纯搬移纪律即可。

P2 验证资产未固化：守门脚本不在版本库里，且测试会漂移

实测 tmp/verify-模块图.mjs（最重要的架构守门脚本）是 untracked 状态——换机器、误清理或 CI 上即失效，等于门禁只存在于这台 Mac。已入库的 verify-collocations.mjs 则是把 提取后续词组/前置词组 函数体以字符串复制进测试再比对源码文本——它测的是「字符串相等」而非「行为相等」，源码改个缩进就假红，改了逻辑忘了同步就假绿。

verify-模块图.mjs 入 git；collocations 测试改为 import 真实模块后跑行为断言（搬移后函数已在 js/查找弹窗.js，具备可 import 的条件）。

P2 状态单例：15 个模块直接读写共享可变对象，耦合是隐式的

实测 15 个文件 import 状态.js，JSDoc 自己也写明「各模块直接读写，无变更通知」。依赖图无环 ≠ 低耦合——它只保证没有循环，「谁在改 状态.字号」这类问题依然只能靠 grep。对单人无框架项目这是务实选择（且已有 排版键 签名机制缓解重排传播），暂不必推翻，但它是未来一切诡异 bug 的温床，值得有意识地控制：新增模块优先参数传递而非直接摸单例。

P3 次级问题（不阻塞，按顺手程度处理）
  • 文本管线纯度打折：不直接 import 状态.js（好），但 import 了 排版引擎.js 的 计算句段负担，而排版引擎整模块 import 状态+元素。该函数本身是纯函数（实测无状态引用），但「纯计算层」的标签经传递依赖打了折扣。可把 计算句段负担 挪入常量或独立纯函数模块。
  • 常量.js 藏可变状态：高亮配色[0].深色/浅色 在 app.js 与 字体设置.js 被直接突变。常量模块语义上是不可变数据源，实际是共享可变状态——import 顺序敏感，测试/热重载下会状态泄漏。
  • localStorage.setItem 无异常防护：隐私模式/配额满时抛 QuotaExceededError。多数调用点在事件处理器里影响面小，但 保存持久化状态() 全库读写（每次保存都 JSON.parse 整个书库再写回）在书多了之后会成为性能项。
  • 语音订阅.js 断线无重连：onclose 只 console.warn。语音服务器重启后必须手动刷新页面才能恢复语音控制。
  • 重构适用性评估.md 论据过时且前后矛盾：「架构特征」一节仍写「app.js 是单一脚本……无 import/export」，「代码库结构」一节却写「已拆入 js/ 模块」；还引用了已不存在的 hqmx_*.xlsx。文档结论（不引 Vue/React）依然成立，但论据需要一次刷新，否则误导未来的读者（包括未来的你）。

三、总评

以「巨石拆解」为目标衡量，这次重构的成功率是高的：量化目标达成（-43%）、行为零回归有证据链（逐字比对 + E2E 8/8）、断环手段专业、验证密度超出项目基础设施水平。它没有犯重构最常见的错误——边搬边改、顺手优化导致行为漂移。
