## 1. 架构总览：一条清晰的四层链

整个系统是一条单向分层链，模块图无环由 CI 门禁（`tmp/verify-模块图.mjs`）锁住：

┌─ 组合根 ─────────────────────────────────────────────────────┐
│ app.js（22 条依赖边）：启动、事件绑定、载入编排、语音入口        │
│ 语音订阅.js：独立入口，仅经 常量.语音事件 解耦，反向派发 CustomEvent │
└──────────────────────────────────────────────────────────────┘
            ↓（依赖注入断环：注册右下强制显示 / 注册自动滚动滚轮监听
               / 初始化滚动条拖拽 / 初始化内容选择弹窗）
┌─ 交互层（语义模块，模块级私有状态）─────────────────────────────┐
│ 键盘控制 / 自动滚动 / 跳转动画 / 正文交互 / 关键词手势 / 滚动条    │
│ 右下控件 / 指示器 / 面板 / 查找弹窗 / 词频弹窗 / 内容选择弹窗      │
│ 字体设置 / 关键词 / 错误提示 / 统计展示                          │
└──────────────────────────────────────────────────────────────┘
            ↓
┌─ 计算层（不触 DOM 或仅触一次）────────────────────────────────┐

## 2. 四条核心数据流走查

### 2.1 文本载入管线（app.js:245–307 → 应用文本 810–1023）

七段异步管线，每段带 `载入仍然有效()` 令牌检查，让出点由 调度.js 统一：

```text
fetch → UTF-8 解码 → 规范化(CRLF/？) → 引文索引 → 句子换行
→ 阶梯断点 → 句段负担前缀和 → 单字统计 → 行索引(含排版参数变化重试)
→ 一次性提交(状态.* 12 个字段) → 恢复阅读位置/关键词 → 渲染
```

排版参数在 await 期间变化的竞态有专门处理（app.js:907–918 重试循环、排版引擎.js:60–69 排版变化重启），并有 `tmp/verify-layout-race.mjs` 锁定。这段管线的正确性设计是全仓最扎实的部分。

### 2.2 渲染管线（排版引擎 → 虚拟渲染）

- 行索引是全文一次性的字素精确测量：中文 1em 固定宽、西文 Canvas `measureText` + 词级缓存、超长片段字素边界二分。产出 `Uint32Array` 四元组（起点/终点/逻辑行/段落）+ 阶梯 `Uint8Array`。
- 渲染窗口按 `scrollTop/行高 ± 12 缓冲行` 计算，重叠时增删首尾片段、非重叠整块 `replaceChildren`，用合成 `translateY` 定位避免逐行 top 布局（虚拟渲染.js:77）。
- 关键词命中用每个关键词一个游标 + 二分定位相交命中，随窗口推进单调前进，均摊 O(1)。
- 指示器按「轨道像素反查命中」绘制，代价只与轨道高度相关；底图/段缓存按布局键失效。

### 2.3 跳转与滚动

- 跳转动画（跳转动画.js:201–311）：rAF + 平方缓动，边框横移经「先滚到终点测量、再滚回起点」的双渲染实现；迸发粒子用 `offset-path` 二次曲线。
- 自动滚动（自动滚动.js:438–538）：指数缓动速度、密度自适应（前缀和二分 O(log 段数)）、每帧合成小数位移补偿 Chrome 整数像素 scrollTop、界面节流 50ms、统计每 30s 落盘。
- 滚动条/进度条共用「轨道中心 ↔ 滚动位置」双射（滚动条.js:168–192），指示器刻度与滚动块共用同一坐标。

### 2.4 持久化（持久化.js）

- 单键 `localStorage`（v2），带 v1→v2 迁移、解析缓存按原始串失效、损坏回退 + 备份后覆盖策略，`tmp/verify-persistence-migration.mjs` 用 18 个用例锁定了这条策略链——这是全仓测试密度最高的模块。
- 保存防抖 120ms；`pagehide`/`visibilitychange` 即时落盘。

## 3. 上轮 P1 复核：四组仍然成立，其中恢复窗口本轮给出更精确的定位

上轮评审的 4 组 P1 在当前代码全部复核成立，且我都找到了独立于上轮论证的代码路径证据：

1. **恢复不是事务（仍成立）**。本轮补充精确窗口：`app.js:888` 的 `恢复阅读设置()` **同步**改写全局设置与 18 个 CSS 变量后，`app.js:894–918` 的行索引构建存在多个 await；在 await 期间 `状态.文件名` 仍是**旧书**、`状态.行起点列表` 仍是**旧索引**（非空，因此 `保存持久化状态` 的守卫条件放行）。此时若 `visibilitychange→hidden` 触发保存（app.js:506–510 已注册），**新书的排版设置会写进旧书记录**。这是比"半恢复状态"更具体的跨会话污染向量。失败路径同理：`恢复阅读设置` 内部任意 `TypeError`（字体设置.js:937 起）都发生在旧会话 DOM 已被改动之后。
2. **异步错误路径无所有权（仍成立）**。`app.js:300–302` 的 catch 不检查 `本次载入序号 === 状态.载入序号`；`排版引擎.js:47` 的 `执行重建().catch(显示文本处理错误)` 不检查排版任务序号。旧任务的异常仍可覆盖新任务的 UI。0 处 `AbortController`（实测）意味着 fetch 也只能靠序号事后丢弃，无法真正取消。
3. **持久化整库读改写（仍成立）**。0 处 `storage` 监听（实测），无修订号、无冲突检测；写入失败仅 `console.warn`（持久化.js:239–242），用户不可见。
4. **文本身份 = 文件名 + 长度（仍成立）**。0 处指纹（实测），`app.js:975–977` 仅双字段判定；`app.js:249–251` 同名直接 return，无重载入口。

上轮 9 组 P2（状态无变更协议、设置四形态、双组合根、渲染器内嵌语言规则、汉字定义不一致、两套命中语义、错误可观察性、目录索引依赖、知识库边界）同样全部成立；其中两套命中语义本轮实测到具体行：`关键词.js:245`（命中后前进一个字素 → 允许重叠）vs `查找弹窗.js:227`（前进整词 → 不允许重叠）。

## 4. 本轮新增发现（上轮评审未覆盖）

### 新-1【P2】「模块加载不触 DOM」只是注释纪律，基础层自己违反，测试基建正在为它付出代价

`排版引擎.js:185`、`指示器.js:11`、`跳转动画.js:34` 都用注释宣告"模块加载不触碰 DOM，便于静态加载与测试"，但基础层恰恰做不到：

- `常量.js:1` 在模块求值期执行 `new URL('./txt/', document.baseURI)`；
- `状态.js:165` 在模块求值期执行 99 个 `querySelector`。

后果已经固化在测试基建里：三个行为测试各自手写了一套**不同的** `globalThis.document` Proxy stub（verify-collocations.mjs:11–38、verify-keyword-search.mjs:3–31、verify-layout-race.mjs:1–34）才能在 Node 加载真实模块。每新增一个模块级 DOM 触点，这三套 stub 就要各自补丁一次，且**没有门禁会在 stub 漂移时报警**——下一个纯函数测试作者要重新发明第四套 stub。

**建议**：要么把「模块求值期零 DOM 触碰」升级为全仓约束（`文本目录地址` 延迟到首访、`元素` 表改为 `初始化()` 填充），并在 verify-模块图 里静态扫描模块顶层的 `document`/`window` 引用；要么承认现状，把 stub 收敛成一个共享的 `tmp/stub-浏览器.mjs`。二选一，别让纪律只活在注释里。

### 新-2【P2】`统计全文单字` 名不副实，且造成每次载入的重复全文扫描

`文本管线.js:473–501` 的 `统计全文单字` 实际返回的是**全文出现次数恰为 1 的汉字集合**（`频次 === 1` 过滤），不是"全文出现过的单字"。三处不一致：

- `状态.js:108` 的 JSDoc 写"全文出现过的单字集合（**词频分析用缓存**）"——但词频弹窗（`词频弹窗.js:195` `统计全文词频`）完全不用它，自己做了一遍独立全文扫描。注释是错的。
- 真正的消费者是 `虚拟渲染.js:211`（渲染"全文唯一字"标记），这是 README 未记载的显示特性。
- 成本上：每次切书做一次全文单字扫描（`app.js:289`），按 Ctrl+A 词频分析时再做一次全文扫描——两次扫描互不复用，虽然都有时间片让出，不构成卡顿，但属于同一份文本的两套独立遍历。

**建议**：重命名为 `统计全文唯一字`，修正 `状态.js:108` 注释；若词频分析愿意复用，可以让 `统计全文词频` 顺带产出唯一字集合，载入时懒统计（首次渲染到含唯一字的行才触发）。

### 新-3【P3】键盘快捷键的「输入目标守卫」不一致

`键盘控制.js` 里四个全局快捷键的守卫标准不同：

| 快捷键 | 守卫 | 位置 |
| --- | --- | --- |
| Ctrl+A（词频） | `!是可编辑目标` | 键盘控制.js:154–165 |
| Ctrl+F（查找） | **无** | 键盘控制.js:167–178 |
| Ctrl+D（自动滚动） | **无** | 键盘控制.js:182–196 |
| Ctrl+S（字体） | **无** | 键盘控制.js:199–214 |

焦点在输入框/弹窗内时按 Ctrl+D 会突然启动自动滚动并劫持浏览器书签快捷键，Ctrl+S 会弹出字体设置（而非保存）。翻页键有 `是交互目标` + `有弹窗打开()` 双守卫（键控制.js:259–287），Z/X 按键滚动同样有——唯独这三个无守卫。行为应当统一：要么都查 `是交互目标`，要么在注释里显式声明"全局快捷键有意穿透输入焦点"。

### 新-4【P3】`翻页整屏` 的会话结束原因硬编码为「语音翻页」

`键盘控制.js:54`：`翻页整屏()` 由 Space/Enter/方向键/语音四种来源共用，但内部固定调用 `结束跳转会话('语音翻页')`。控制台里所有键盘翻页都被记录为"原因: 语音翻页"，日志失去归因价值。翻页原语应接受来源参数（调用方 `处理键盘按下` 已计算了 `翻页来源`，只是没传下去）。

### 新-5【P2】内容选择弹窗为显示字数整本下载全部书目，且关闭后不可取消

`内容选择弹窗.js:57–110`：打开弹窗即对 `状态.文本目录` 里**每个**文件发起完整 `fetch → arrayBuffer → TextDecoder`，仅为了统计非空白字符数。三点代价：

1. 书库大时（数十本书 × 数 MB）内存与带宽峰值不可控，`Promise.all` 使所有下载**并行**；
2. 0 处 `AbortController`（实测）——关闭弹窗后所有在途下载继续跑完并写共享缓存；
3. 字数缓存在 `状态.文本字数`（会话内存级），刷新即失，下次打开重新全量下载。

**建议**：字数统计降级为可见时懒加载（IntersectionObserver 只统计视口内的条目）或由本地服务器提供 `txt/manifest.json`（含字数/大小，与上轮"显式清单"建议合并为同一项工程）；至少给 fetch 接 `AbortController` 并在 `close` 时中止。

### 新-6【P3】指示器更新链路的固定副作用

`指示器.js:24–26`：`更新关键词指示器()` 每次都先调 `渲染关键词面板()` + `更新滚动块()`。而 `渲染关键词面板`（面板.js:70–78）在签名短路**之前**就执行 `document.body.classList.toggle('右下面板展开')`——即每次指示器更新（包括每次跳转、每次关键词变化、悬停切换）都会做一次 body class 写 + 两个 hidden 写。`classList.toggle` 同值写很便宜，不构成性能问题，但它意味着"签名拦截了所有冗余重建"的注释承诺只对 DOM 子树成立，对副作用不成立。属于精确性小瑕疵，顺手修即可。

### 新-7【P3】`读取持久化数据()` 与 `设置文本/设置属性` 的所有权残留

- `持久化.js:27` `读取持久化数据()` 生产代码 0 调用（实测仅测试使用），上轮已提出，本轮确认仍在——它抛错的语义（`throw 读取结果.错误`）与业务入口 `读取持久化数据或新建`（回退策略）不同，留着会诱导未来调用者选错入口。
- `设置文本`/`设置属性` 两个通用 DOM helper 仍住在 `虚拟渲染.js:602–612`，被 滚动条/自动滚动 反向引用——渲染模块成了工具箱，归属仍未迁（上轮 P3 确认仍成立）。

## 5. 架构强项（应当保持不被重构破坏的部分)

1. **无环依赖图 + CI 门禁**。`verify-模块图.mjs` 同时校验具名导出存在性与环，这把"拆模块"的成果变成了不可回退的资产。
2. **断环模式统一且显式**。四个依赖注入点（右下强制显示、滚轮监听、滚动条拖拽中断、内容选择回调）都在源码注释里写明了断的是哪条环。后来者能看懂为什么。
3. **调度纪律**。全仓唯一让出点 `调度.js`（实测 0 处裸调），时间片 8ms、按 4096 项节拍检查任务有效性——大文本处理不冻结 UI 的根基。
4. **类型化索引 + 二分无处不在**。行索引、句段前缀和、命中位置全部 `Uint32Array/Float64Array`；`查找偏移所在行`、`二分句段起点`、`查找首个相交命中`、`查找首个未结束引文` 构成一套一致的 O(log n) 查询原语。
5. **竞态意识**（成功路径）。载入序号/排版任务序号/词组分析序号/词频任务对象同一性，四套令牌覆盖了全部成功提交路径，且布局竞态有专门测试。
6. **持久化策略链测试密度高**。18 个迁移/损坏/回退用例，备份-后-覆盖策略被锁定。
7. **性能细节成体系**：滚动 rAF 节流、指示器离屏画布双层缓存、面板渲染签名拦截、滚动块文本限频更新、自动滚动合成层小数补偿、每界面节拍只读一次布局度量。

## 6. 结构性结论：问题集中在「图之外的协议」

依赖图是健康的，真正的架构债务全部集中在四类**运行时协议缺失**上，与上轮结论一致并经本轮独立复核：

| 缺失协议 | 可观测症状（实测） | 后果 |
| --- | --- | --- |
| 状态变更协议 | 36 个保存触发点、23 个强制渲染点手工配对 | 漏一处即"本次有效、重开失效"类延迟故障 |
| 提交/恢复事务 | 恢复窗口跨 await 改写已提交会话（§3.1） | 损坏数据可污染旧书记录，失败留中间态 |
| 任务所有权（异常路径） | 0 个 AbortController、4 套互不复用的令牌 | 旧任务异常覆盖新任务 UI；取消只防提交不防副作用 |
| 数据身份与并发 | 0 个指纹、0 个 storage 监听、单键整库读改写 | 同名同长文件错恢复；多标签页静默丢更新 |

治理顺序维持上轮评审的阶段 0→4 不变（先失败路径门禁，再恢复事务与任务作用域，再状态命令与设置描述表，再身份/存储模型，最后领域与发布边界）。本轮新增发现并入对应阶段：新-1 并入阶段 0（测试基建）、新-3/新-4/新-6/新-7 并入阶段 2/4（顺手项）、新-2 并入阶段 4（领域语义统一）、新-5 与「显式清单」合并入阶段 4。

## 7. 摘要

当前架构是一套**分层真实、性能工程扎实、但提交协议缺席**的系统：文本管线、排版引擎、虚拟渲染和持久化策略链达到了可测试、可推理的工程质量；而全局状态单例 + 手工刷新/保存配对 + 无事务恢复 + 序号式取消，构成了所有已知 P1/P2 问题的共同根源。下一阶段最有价值的工作仍然不是拆文件或换框架，而是把上轮评审的"会话草稿 → 一次提交"和"统一任务作用域"落成代码——它们能同时消除 §3 的全部四组 P1，并把 36 个保存点、23 个渲染点的配对责任从 12 个模块收回到一个调度器。
