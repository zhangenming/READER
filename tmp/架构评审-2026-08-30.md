# READER 架构评审 · 2026-08-30

> 范围：全仓 13,114 行（app.js 1,037 + js/ 24 模块 ~7,400 + styles.css 2,960 + index.html 579）。
> 方法：全模块通读 + 依赖图实测 + 元素表/HTML 交叉校验 + node --check 全量语法检查。
> 仅评审，未改动任何业务代码。

## 结论先行

前两轮重构（8-26 评审及其后续修复）质量高：巨石已拆干净、依赖图无环、管线是可测的纯函数层、四种异步竞态都有防护、上轮 P1（启动异常路径）与 P3 全部修完（collocations 测试已改 import 真模块、语音已加重连、高亮配色已迁出常量、localStorage 写入已容错）。

**剩余问题不再是"巨石"，而是六个结构性热点 + 一批卫生项。** 核心矛盾收敛为一句话：**状态层没有变更通知，导致"刷新什么、何时保存"的知识散布在全仓 16 处手动编排和 35 处保存调用里；而同一份"设置字段清单"又以四种形态重复存在。** 这两件事是当前所有"改一处漏一处"风险的共同根源。

## P1 · 结构性热点

### 1. 状态单例无变更通知 → 全仓手工编排（最大风险源）

`js/状态.js:50` 自己写明"各模块直接读写，无变更通知"。实测后果：

- 「渲染可见行(true) + 更新关键词指示器() (+ 显示当前命中位置提示/安排保存)」三连在 **16 处**重复（关键词.js、正文交互.js、跳转动画.js、键盘控制.js、字体设置.js、app.js、查找弹窗.js…）。任何新交互点漏调其一，就产生陈旧画布或陈旧指示器，且没有测试兜底。
- `安排保存持久化状态()` 直接调用点 **35 处、分布 8 个模块**（字体设置 17、自动滚动 5、app 4、键盘/跳转/正文/关键词/面板各 1-2）。持久化时机是"每个突变点自己记得调"，不是"状态层感知变更"。
- 建议方向（不引入框架）：状态层加一个极薄的失效标记 + `安排综合刷新()`（rAF 合并：渲染可见行 → 指示器 → 面板签名 → 安排保存），把 16 处三连收敛为 1 处；或至少导出一个 `刷新全部视图()` 供组合根统一编排。

### 2. 状态.js 从"叶子层"长成了混合层

- 统计域业务逻辑 `确保今日滚动统计` / `结转未入账滚动毫秒`（`js/状态.js:293-331`）为断环下沉到了状态层——环确实断了，但代价是"叶子状态层"现在包含：DOM 引用表（97 个 querySelector）+ 60 余字段单例 + 统计记账 + 日期工具。建议把统计记账独立成 `统计.js`（持久化与自动滚动都可直接依赖，不成环），状态层回归纯数据。
- **计时器字段混进公共单例**：`尺寸计时器`(app 用)、`保存计时器`(持久化用)、`迸发计时器`/`衔接线计时器`(跳转动画用)、`当前命中位置计时器`(虚拟渲染用)（`js/状态.js:131-135,147`）。这是四个模块的私有运行时状态，本应像 `自动滚动.js` 那样用模块级 `let`，放公共单例只会让"谁清谁的计时器"更难追踪。
- 关键词对象（{id, 文本, 命中位置, 当前命中idx, 配色idx, 临时}）在 关键词.js / app.js / 持久化.js 三处各自构造/拼装，无统一工厂或 JSDoc 类型。

### 3. 单本书设置损坏 → 整本书打不开，且错误文案误导

恢复粒度不对称：库级损坏有空库回退（README 已承诺），但**书级损坏会硬失败**——`恢复阅读设置`（`js/字体设置.js:863`）对字号/行高/速度/排序等逐项 throw TypeError/RangeError，异常沿 `应用文本` 上抛到 `载入文本` 的 catch，该书直接进错误页，只能手改 localStorage 解救。

更糟的是文案链：`js/错误提示.js:4-8` 把**一切 RangeError 映射成"文本过大，超出了 Chrome 的安全滚动高度"**——一本 30 万字的普通小说因设置损坏会提示"文本过大"。建议：书级恢复失败时按"该书空设置 + 保留关键词尽量恢复"降级重试，并把"设置无效"与"文本过大"两类错误分开。

### 4. 同一份"设置字段清单"以四种形态重复

加一个设置项（如新颜色开关）今天至少要改 4 处：

1. `js/持久化.js:170-213` 保存序列化（手写字段名）；
2. `js/字体设置.js:863-1184` `恢复阅读设置` 反序列化+校验（手写同名字段）；
3. `app.js:859-886` 上一本书公共状态继承白名单（手写第三遍）；
4. 各 `设置*` 函数本体 + 14 个 CSS 变量名字符串（`--引文字体` 等散布在 设置/恢复/读取正文排版 三处）。

且**读路径与写路径分家**：写（序列化）在 持久化.js，读（反序列化+校验+应用）却在 字体设置.js——查一个字段的往返要在两个文件间跳。建议以一张「设置字段描述表」（字段名、默认值、CSS 变量、校验器、序列化器）为单一数据源，保存/恢复/继承/校验全部由表驱动。

## P2 · 设计问题

### 5. 键盘控制.js 成为新耦合枢纽（拆分把组合根职责转移到了键盘层）

- `js/键盘控制.js:1-25` import **12 个模块**，其中直接 import 三个弹窗模块（字体设置/词频弹窗/查找弹窗）——键盘层绕过组合根直接开 UI。
- 导航域核心 `执行导航跳转` 住在键盘控制里，导致 `关键词手势.js:3`、`正文交互.js:5` 这些不关心键盘的模块也必须依赖它，形成 手势 → 键盘控制 → 三个弹窗 的传递依赖。
- 处理函数本体是 500 行 if 链，无快捷键表抽象；每加快捷键要往状态机多处补 if 和"取消待定导航"补丁（Ctrl按键状态 已在 5 个分支里手动清空）。
- 建议：抽 `导航.js` 承载 执行导航跳转/跳到命中 编排；弹窗打开动作收敛为一张快捷键表（键 → 动作），由组合根或独立 快捷键.js 分发。

### 6. 字体设置.js 是 UI 层的第二块巨石（1,184 行、5 种职责）

弹窗开闭/标签页渲染/字体重细/6 类颜色设置/排版开关重建，外加 320 行持久化反序列化，全在一个文件。"设置*函数重复『等于默认值 → removeProperty，否则 setProperty』模式"出现 6 次。与 P1-4 一并解决。

### 7. 虚拟渲染.js 的渲染循环内嵌内容语义规则

名义上的"虚拟渲染"实际承担了内容标注规则引擎：

- 人称代词字形替换 W/T/N（`js/虚拟渲染.js:200-210`）、的/了 特殊字形、不字否定叉、人称代词判定（229-239）、**50 字符的关系字字符串字面量直接写在渲染循环里**（241-243）、关系连词邻接判定（254-265）。
- 这些语言规则既不可单独测试，也与 DOM 构建深度耦合；项目已有 搜索.js "纯查询层"先例，应同样抽一个 内容标注.js 纯函数层（入参文本偏移，出参类名集），字面量进 常量.js。

### 8. 测试盲区 + 测试资产放 tmp/

- 五个 verify 覆盖：模块图、持久化迁移、词组提取、关键词字素、布局竞态。**未覆盖**：建行索引（最复杂纯算法）、恢复阅读设置（恰是 P1-3 的风险点）、统计记账（结转/跨日归零）、虚拟渲染关键词游标。
- `js/状态.js:165-264` 的 97 个 `querySelector('#id')` 与 index.html 的 103 个 id **今天同步，但无静态校验**——verify-模块图 stub 掉了 document，id 改名只能运行时炸。一行脚本即可交叉校验，建议补进 npm test。
- 测试住在 `tmp/`（目录名暗示可清理），npm test 依赖它；tmp/ 还混着 ps/、test-dark.html、截图基线等杂物。应迁 `verify/` 或 `tests/`。

## P3 · 卫生项

9. **无 .gitignore**：.DS_Store 已入库；`.reasonix/`、`.workbuddy/`、`.openclaw/`、`.claude/`（AI 工具的个人记忆/状态）全部进了版本库——噪音、隐私与跨机冲突风险。
10. **持久化全库重写**：每次保存 `JSON.stringify` 整个书库（所有书状态），书多/关键词多后是性能与 localStorage ~5MB 配额风险；v2 结构无内嵌 version 字段，演进只能整体换键迁移。
11. **默认文件名硬编码**（`js/常量.js:2-3`）：写死一个 z-library 下载文件名；文件缺失时启动即"文本载入失败"。内容选择弹窗已有目录读取能力，启动可回退到目录首个文件。
12. **语音订阅无条件常驻**：无需语音也每 5 秒重连 wss://localhost:15941 并刷控制台警告；地址可用 ?ws= 覆盖但无 ?voice=off 开关。
13. **四种竞态取消习语并存**：载入序号 / 排版任务序号 / 词组分析序号 / 词频任务对象同一性——各自正确但可统一为一种任务令牌，降低理解成本。
14. **`设置文本`/`设置属性` 通用 DOM 工具住在 虚拟渲染.js**（`js/虚拟渲染.js:602-612`），消费者是 自动滚动/滚动条——应迁 文本工具.js 或独立 dom工具.js。
15. **app.js 应用文本 仍是 ~210 行上帝编排**：5 阶段管线调用 + 继承白名单 + 状态重置清单 + 恢复 + 渲染 + 日志。"随书切换必须重置的字段"隐式散在 `app.js:920-937`，新增字段忘记重置即跨书脏状态；建议在 状态.js 提供 `重置本书状态()` 与字段清单同源。
16. **文档又漂移**：重构适用性评估.md 仍写"app.js 约 1425 行、23 模块"（实际 1,037 行、24 模块）；上轮同样指出过文档漂移——结构事实建议由 verify-模块图 顺带输出统计，文档引用之。
17. 文件权限不一致（搜索.js/统计展示.js/面板.js/文本管线.js/tmp/verify-模块图.mjs 为 600，其余 644）。
18. `读取持久化数据()` 已无生产调用方（仅测试用），可标记或合并。
