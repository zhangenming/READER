# 性能评审 · 2026-09-08

范围：全仓 25 个 JS 模块 + index.html + styles.css 热路径，配 `tmp/bench-hotpaths.mjs` 对最大文本（笑傲江湖，989,543 字符）实测。

## 总体结论

架构性能基础扎实，多数经典大文本陷阱已被正确处理：虚拟滚动只渲染视口±12 行、`contain: content` 隔离每行布局、逐字 span 但用 DocumentFragment 一次插入、滚动事件 rAF 节流、自动滚动每帧只写 transform/scrollTop 且界面更新按 50ms 节拍节流、指示器画布双层缓存（布局键 + 底图/段缓存，滚动完全不重绘）、面板签名比对跳过无谓重建、持久化 120ms 防抖 + 会话内快照缓存避免反复 JSON.parse。**真正的瓶颈集中在「载入管线重复扫描全文」与「逐字 DOM 粒度」，前者有约 2 倍总耗时可省，后者是剩余的主要帧成本但动它属于重构级变更。**

## 实测数据（Node 22 / Apple Silicon，《笑傲江湖》989,543 字符）

| 热点 | 实测 | 评价 |
|---|---|---|
| 统计全文单字（载入必经） | 52 ms | 主要可优化点，见 P1 |
| 同算法 charCodeAt 对照 | 4–5 ms | 约 13 倍差距 |
| 规范化文本 | 4 ms | 无需优化 |
| 引文索引 / 句子整理 / 句段负担 | 30 / 16 / 11 ms | 各自独立扫描全文，见 P2 |
| 关键词命中扫描 8,337 次命中（`containing`/次） | 1–2 ms | **疑点排除**：Intl.Segmenter.containing 并不慢 |
| 查找字素终点 ×697 次 | 1 ms | **疑点排除**：非安全码点极少，无碍 |

## 瓶颈清单（按优先级）

### P1 载入必经：`统计全文单字` 用 `for...of` + Map —— 白丢约 50ms/百万字

[文本管线.js:473](../js/文本管线.js) 每个字符走 String 迭代器（含代理对合并与字符串分配）+ Map 哈希计数。百万字文本实测 52ms。换成 charCodeAt 环绕 + BMP 频次 Uint32Array、只对罕见扩展平面字回退 Map，可降到 ~5ms。这是无任何行为风险、纯赢的一处。
顺手可合并 P2 的第三次扫描，再省一次全文遍历。

### P2 载入管线：同一文本被顺序扫描 5 遍

[app.js:859 应用文本](../app.js) 依次 await：规范化(1) → 引文索引(2) → 句子整理(3) → 阶梯断点(4) → 句段负担(5) → 统计全文单字(6)。每遍都有 `按需让出主线程` 调度开销，且 2/4/6 读的都是几乎相同的字符流。三项低耗时（引文 30ms、句子 16ms、负担 11ms）暂不值得合并；但「阶梯断点默认关闭（`阶梯段落启用: false`）时仍全文扫描」值得改成惰性：首次开启阶梯段落时再建，默认载入直接省一遍扫描。若未来支持 5MB+ 文本，再考虑合并为单遍多产物扫描。

### P3 创建行索引：普通中文行被逐字符 `charCodeAt` + 范围判断

[排版引擎.js:139](../js/排版引擎.js) 主循环每字符做码点提取与 6 组范围比较，再每片段做宽度测量（中文宽度恒为 `排版.正文字号`，`测量范围` 有快路径，好）。对 100 万字这一步在浏览器里是载入最重阶段（console 里「行索引」耗时遥遥领先其他阶段）。可优化：BMP 常见区（0x4E00–0x9FFF 等）先用一张 64K 布尔查找表（`是安全字素码` 已按范围写死，可预生成 Uint8Array 表）替代多组比较；对连续安全 BMP 段先批量切分再统一赋宽度，减少每字符函数调用。预计该阶段可省 30–50%。非紧急，因为已有时间片让出，不卡 UI，只是加长「打开书」的等待。

### P4 渲染热路径：逐字 span 的 DOM 规模 —— 最大的持续帧成本

[虚拟渲染.js:99-465](../js/虚拟渲染.js) 每个可见字一个 `<span class="字">`，外加命中标记、否定叉、关系字、全文单字、引文跨行等多个子 span/类切换。每屏约 45 行 × ~30 字 ≈ **1,300–1,500 个 span/屏**，滚动时按方向增删几百个。逐字粒度是「点击任意字定位关键词命中」交互的地基，不能直接砍。可行的低风险减压：
- 4a) `.字:not(.西文){width:1em}` + `display:inline-block` 每字都进行内格式化上下文，比纯文本行排更贵。中文相邻字之间的 `</span><span>` 边界本身就是天然边界——若把「无任何特殊类/命中的连续字」合并为一个 span（交互用 `data-start/end` + 事件委托仍可定位到字），span 数可降 60%+。代价：`aria-label`/样式类粒度变粗，需要核对「我他你替换显示」「关系字色」等逐字特性只在命中/特殊字处保留细粒度。这是重构级，建议单独立项做原型验证。
- 4b) 低成本立即项：`显示当前命中位置提示` 三次 `querySelectorAll` 全可见内容扫 1,500 元素，仅在跳转时触发，可先保留；`切换同组高亮` 悬停时全量扫 `.字.命中`（[正文交互.js:351](../js/正文交互.js)），命中多时鼠标划过正文会连续触发——建议只在悬停关键词确实有可见命中时才循环，且把循环范围从 `.字.命中` 收窄到本次渲染窗口中该关键词的命中元素（渲染时可顺手记录每关键词在本窗口的命中元素数组）。

### P5 每帧强制同步布局：`更新滚动块位置` 每帧写 transform 前读 `scrollTop`

[滚动条.js:218](../js/滚动条.js) 自动滚动每帧调用，读 `元素.滚动容器.scrollTop`（读布局）后写两个 transform。rAF 回调里同帧先读后写尚可，但 [自动滚动.js:532-535](../js/自动滚动.js) 同帧还有 `渲染可见行` 的 DOM 增删 + 可见内容 transform 写入。目前顺序是「读度量 → DOM 增删 → 写 transform」，DOM 增删发生在读度量之后，同帧内的 invalidate-layout 风险被规避，属「正确但脆弱」：任何人在中间插一个读布局的调用就会强制重排。建议在 `执行自动滚动` 顶部一次性取齐本帧全部度量（已有 视口度量 注入机制，扩大它即可），并加注释封死这个顺序契约。

### P6 CSS 热路径：伪元素与 box-shadow 数量

命中徽标 `::after`（box-shadow 0 2px 7px）、当前命中准星 4 层 linear-gradient 拼框、否定叉每字 2 个 rotate 伪元素、引文条 `::before` 每字一个。这些只作用于「命中/特殊字」，常规屏内数量有限（命中数取决于用户标记），实测滚动无明显掉帧来源。`will-change: transform` 只加在可见内容与滚动块，节制正确。无需改动，仅提示：如果将来「关系字红色短横线」(`.关系词首字::after`) 在密集中文里数量激增（该类基于内置词表，每屏可能几十个），重绘面积会上升，届时可改为整行一个装饰层。

### P7 次要点

- **键盘控制兜底跳转** [键盘控制.js:479](../js/键盘控制.js)：无当前关键词时把所有关键词全部命中展开排序 O(N log N)，关键词多且命中多时一次按键上百万元素。触发频率低，量级可控，可加一句命中总数上限保护。
- **上下文弹窗初始渲染**：`上下文最大初始行数 = 2000`，首开即建 2000×4 span ≈ 8,000 节点，中等卡顿一次。可把初始块降到 200（与分块一致），靠滚动预载补齐；「定位到当前命中」场景再按需扩到目标行。
- **词频弹窗**：六字重叠滑动 + Map 每字符 6 次 set/get，百万字 ~600 万次 Map 操作，有分片让出不卡 UI 但总耗时秒级。低频功能，可接受；若要优化，先只统计选定字数页（懒算其他页）。
- **查找/内容选择**：250ms 防抖 + 全文 indexOf 扫描，实测 1ms 级，已排除嫌疑。
- **`获取当前命中行位置/边框`** 的 `querySelector` 属性选择器（`[data-keyword-id="..."]`）在跳转路径调用，可见 1,500 span 中查找，单次 <1ms，无碍。

## 已排除的疑点（免后人重查）

1. `Intl.Segmenter.containing` 逐命中调用不慢（8,337 次 1–2ms）。
2. `查找字素终点` 的成倍扩窗 segment 重试，非安全码点占比 <0.1%，无碍。
3. 指示器刻度「逐像素反查」确实是 O(轨道高) 而非 O(命中数)，与注释宣称一致。
4. 持久化读取有会话缓存（原始数据同一性判定），滚动期间 30s 一次落盘 + 120ms 防抖，不会反复 JSON.parse 全库。
5. `.正文行` `contain: content`、空行遮色用 border 而非额外元素、`overflow-anchor: none` 防 EMS 锚定滚动漂移——均已正确。

## 建议落地顺序

1. **立即**：P1 重写 `统计全文单字`（charCodeAt + 频次数组），P2 阶梯断点惰性化。合计把最大文本载入管线砍掉约 60–80ms 与一遍全文扫描。
2. **短期**：P4b 悬停高亮收窄循环范围；P5 帧内度量契约注释化。
3. **重构立项**：P4a 合并无样式字 span；P3 行索引主循环查表化。
4. **观望**：P6、P7 其余项，等真实卡顿反馈再动。
